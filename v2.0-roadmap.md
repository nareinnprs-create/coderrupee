## F. Team Sync - multi-user collaboration on one project (founder + cofounder + staff)

Goal: multiple people working on the same project with **no overlapping edits, no lost
work, and development that always moves forward**. Built on infrastructure that already
exists in CoderRupee: `coderrupee attach` (multi-client to one server), durable server-side
sessions, guarded checkpoints, git integration, and the Cloudflare Pages/Workers + team
config layer (B1/B3).

### Design principles
1. **Single-writer authority per session** - one session, one active driver; everyone else views or queues.
2. **Work isolation per person** - each person edits in their own workspace slice (worktree or attach-mode central server).
3. **Checkpoint everything** - every guarded checkpoint is pushed to a per-person rescue ref on the shared remote before risky operations.
4. **Coordination before collision** - presence + work claims make overlaps visible before they happen, not after.
5. **Guided merges, never silent ones** - integrating two people's work is agent-assisted, tested, and human-approved.

### Planned items

- [ ] **F1. Attach-mode team server (recommended foundation)** - one `coderrupee serve` hosts the project; founder + staff attach their TUI/desktop (`coderrupee attach` already works). Sessions live in ONE durable store, structurally no sync conflicts. Add: attach auth token (team config B1), per-user identity on attach, audit log of who ran what. Effort: M
- [ ] **F2. Identity & presence** - staff identity (git user or team config), live presence (who is online, which project/session), surfaced in the app sidebar and `coderrupee who`. Transport: team server events, or a Cloudflare Worker for git-mode teams. Effort: S-M
- [ ] **F3. Work claims** - claim registry for tasks/files: before a session starts editing it can check and claim; a second session touching a claimed area gets warned with owner + ETA. Feeds the C1 task orchestrator. Effort: M
- [ ] **F4. Never-lose-work safety net** - every guarded checkpoint pushes `cr/<user>/<session>` rescue refs to the shared remote; crash or mess = restore any checkpoint with one command (`coderrupee restore --from cr/<user>/<session>`). Nothing on any machine is ever the only copy. Effort: M
- [ ] **F5. Git merge coach** - when two people's branches diverge: scratch worktree, agent runs the merge, resolves safe conflicts, runs project gates (C2), presents the result for human approval. Silent auto-merge is never allowed. Effort: M-L
- [ ] **F6. Auto-worktree per staff (git mode)** - for teams not using attach mode: opening a project someone else is active in auto-spawns a linked worktree per user; F5 integrates. Effort: M

### Team-mode decision guide
- **2-5 people, shared machine or box available** -> F1 attach mode (strongest guarantee: one store, zero git conflicts).
- **Everyone on their own machines, git-first** -> F4 + F6 + F5 (rescue refs + worktrees + merge coach).
- **Mixed** -> F1 for the shared project, F4+F6 for the rest.

### Sequence impact
- F1, F2, F4 after the B-layer (team config/budgets) - they share identity/auth.
- F3 with C1 (task orchestrator). F5, F6 after C2 (gates) so the coach can run gates.

## P. Active Stack — always-on in all CoderRupee sessions (APPROVED 2026-11-12)

The founder's active stack ships as always-on defaults for every staff session, and powers
the autonomous v2.0 build itself. All four delivery decisions approved: **bundled** in the
installer (no first-run downloads), **Ponytail baked** into default agent rules, **Strix
release gate ON**, **RTK always-on + bundled**.

The stack:
| Tool | What it does | Source |
|---|---|---|
| Graphify | /graphify — multimodal knowledge graph of any folder; 71.5x fewer tokens per query vs raw files; persistent across sessions | github.com/Graphify-Labs/graphify |
| RTK | terminal output compression for agent shell commands | github.com/rtk-ai/rtk |
| Ponytail | lean/minimal code-generation behavior rules | npm @dietrichgebert/ponytail |
| Caveman + noise-filter + graphify-first rules | output discipline, log-noise filtering, graph-first navigation | local AGENTS.md rules |
| Strix x9 pentest skills | autonomous security audit skills | github.com/usestrix/strix |

### P1. Rules layer — always-on via team config

- [ ] **P1. Rules defaults via team config (B1)** — Caveman output discipline + noise-filter +
  graphify-first navigation + baked Ponytail behavior ship as the default AGENTS.md rules
  served from coderrupee.opraiz.com/team/config.json; founder-editable centrally. Rides B1.
  Effort: S

### P2. Bundled stack in the installer

- [ ] **P2a. License audit** — review licenses of rtk, graphify, strix, ponytail before
  bundling third-party binaries/skills in our installer; add THIRD-PARTY-NOTICES. Effort: S
- [ ] **P2b. Bundle RTK binary** — single-file binary in the installer + always-on: agent
  rule wraps long terminal commands with rtk (token/context savings in every session).
  Effort: S
- [ ] **P2c. Bundle Graphify + Strix skills** — skill files into the CoderRupee skills
  directory at install; available in every session. Effort: S
- [ ] **P2d. Bake Ponytail behavior** — lean code-gen rules into the default agent rules
  (no plugin install needed). Effort: S

### P3. Stack as product capability

- [ ] **P3a. /graphify command + per-project graphs** — /graphify works in every session;
  graphs cached per project. **Accelerator for C5 (repo Q&A)** — the graph IS the C5 index.
  Uses vision-capable model credits (founder/staff API keys). Effort: M
- [ ] **P3b. Strix release gate in CI (ON)** — publish workflow runs a Strix security scan
  on each release candidate before it goes public; scan report attached to the release.
  Pairs with C2 verification gates. Effort: M + CI minutes
- [ ] **P3c. Strix on-demand for staff** — the 9 pentest skills usable by staff agents on
  their own projects. Effort: S (skills bundled via P2c)

### P. Phase 1 — stack powers the autonomous v2.0 build (immediate, starts with build)

- RTK compressing all build/CI terminal output (already active).
- Ponytail + Caveman active on all generated code.
- Graphify graph of the upstream 2.2.7 frontend (1,078 files) + our codebase built BEFORE
  the L1 re-base — cheap persistent navigation of their architecture during the port.
- Strix pentest gate before each v2.0.x release goes public.

### P. Sequencing

1. Phase 1 immediately (build accelerator; starts with v2.0 build).
2. P2a license audit -> P2b/P2c/P2d bundling -> P1 rules (with the B1 wave).
3. P3a with the C5 wave -> P3b gate from the first v2.0.x release -> P3c anytime.

Notes: bundling requires the P2a license audit to pass first; if a license blocks bundling,
fall back to team-config first-run download for that tool and record it. Graphify vision
calls consume model credits (covered by founder/staff API keys).
